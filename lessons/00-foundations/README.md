# 00: Foundations

## Motto

API price is not product cost.

## Problem

AI teams often discuss models as if the billing unit is the product unit. It is not. Users do not buy tokens. They buy completed work: an answered support ticket, a summarized document, a resolved account issue, or a draft analysis that is good enough to use.

## Concept

Tokenomics is the discipline of connecting model usage to product economics. Start with the vocabulary:

- Input tokens: tokens sent to the model, including system prompts, instructions, user input, retrieved context, prior conversation, and tool schemas.
- Output tokens: tokens generated by the model.
- Context window: the maximum working memory a model can process in one request.
- Cached tokens: repeated input prefixes that some providers bill at a discount when cache rules are met.
- Batch pricing: discounted processing for jobs that can run asynchronously.
- Embeddings: vector representations used for retrieval, clustering, search, or matching.
- Reasoning tokens: hidden or explicit tokens used by reasoning models while solving a task.
- Multimodal tokens: billed representations of images, audio, video, or other non-text inputs.
- Tool calls: calls to APIs, databases, code execution, browsers, or internal systems.
- Human fallback: the cost of handing uncertain or failed work to a human.

The product question is not "What did the model call cost?" The product question is "What did the completed task cost, including everything required to make it reliable?"

## Build It

Build a shared vocabulary and a first cost inventory for one AI feature.

Use [templates/ai-feature-cost-sheet.md](../../templates/ai-feature-cost-sheet.md) to identify:

- Task definition
- Expected monthly volume
- Model calls
- Retrieval or embedding costs
- Tool calls
- Retry rates
- Human fallback rates
- Failure costs

## Use It

PMs can use this lesson to scope whether an AI feature is economically plausible. FDEs can use it to expose hidden costs before a pilot becomes production.

## Ship It
